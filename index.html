About

One engineer, every layer of the system

I build software that ships — schema to deployed service, and increasingly the AI layer in between.

I'm a Computer Engineering student at MIT Academy of Engineering (2023–2027) who has spent the last two years working on real systems rather than tutorials: a compliance platform at OBLIQ-in, document-intelligence pipelines, retrieval-augmented AI services, and a hostel-booking product taken from API design through to deployment.

My default stack is Java/Spring Boot and Python/FastAPI on the backend, React or Next.js on the front, with MySQL or PostgreSQL underneath and Docker plus a cloud platform to ship it. When a workflow deserves it, I add OCR, embeddings, or an agent pipeline — always as a component that solves a problem, never as decoration.

I care about the parts that outlive the demo: clear API contracts, migrations that don't lose data, logs you can actually trace, and deployments that survive contact with real users.

02

Contracts over cleverness

Clear REST contracts, explicit data models, and predictable error handling. Novelty belongs in the problem, not the plumbing.

03

AI as a component

OCR, retrieval, and LLM workflows earn their place when they remove real manual work — not because they're fashionable.

04

Ship, then harden

Working software under real constraints beats a polished spec. Deploy early, observe, then make it reliable.

REDROB

AI knowledge platform

A RAG knowledge platform with workspace-scoped auth, asynchronous document ingestion into pgvector, and LangGraph research workflows that answer questions with citations.

FastAPI PostgreSQL + pgvector Redis Celery LangGraph
Repository
Problem

Teams accumulate documents but can't query them together — ad-hoc chatbots lack workspace boundaries, provenance, and a real ingestion pipeline.

Engineering

Uploads land in S3-compatible storage; a Celery worker parses, deduplicates, chunks and embeds into PostgreSQL + pgvector. A LangGraph workflow retrieves under strict similarity thresholds and returns structured answers with citations, with request IDs and task IDs threaded through the logs.

02 · 2025 – 2026

DocuMitra

Document intelligence

An AI document-processing system that extracts text, classifies by department with confidence scores, summarizes, highlights, and routes documents automatically.

Python OCR NLP scikit-learn React n8n
Repository
Problem

Mixed-format documents have to be read, sorted and forwarded to the right team by hand — slow, inconsistent, and un-auditable at volume.

Engineering

An extraction pipeline (PyPDF2, python-docx, openpyxl, OCR) feeds a Naive Bayes classifier scoring 12 departments with keyword evidence; structured fields, summaries and highlighted copies are generated and routed downstream. Team project of six — I led the automation and processing pipeline.

03 · 2025

StayNest

Full-stack booking platform

A PG/hostel booking platform with Spring Boot REST APIs, JWT authentication with role-based access, property search and booking workflows, and a React frontend — deployed on Render.

Spring Boot Java 17 Spring Security JWT MySQL React
Repository Deployment repo
Problem

Students hunt for PG accommodation across fragmented listings; owners have no lightweight system for bookings, check-ins, and tenants.

Engineering

Spring Boot 3 backend with Spring Security, JWT auth, Spring Data JPA over MySQL and mail services; React 19 frontend with map integration and image hosting. Built with a four-person team on Git workflows during the Campus Credentials internship.

04 · 2026

MonArch

Multi-agent AI platform

A multi-agent orchestration platform: LangGraph agents for planning, research, hybrid RAG and vision, wrapped in guardrails, rate limiting, and an evaluation harness.

FastAPI LangGraph FAISS + BM25 Groq Vision Docker AWS
Repository
Problem

Single-shot LLM calls fail on complex tasks — no routing, no grounding in documents, and no protection against injection or hallucinated output.

Engineering

A FastAPI entrypoint fronts a sliding-window rate limiter and PII/injection guardrails; a LangGraph orchestrator routes to planner, researcher, hybrid RAG (FAISS + BM25) and vision agents, with a reflection critic retrying failed passes and an output-faithfulness check at the boundary.

05 · 2026

OrbitPMS

Property management system

Live demo

A hotel PMS covering rooms, reservations, check-in/out and invoicing — FastAPI + PostgreSQL with a React 19 frontend, JWT roles, and database-level double-booking protection.

FastAPI PostgreSQL SQLAlchemy React 19 JWT
Repository Live demo
Problem

Small hotels run bookings, front-desk state and invoicing across spreadsheets, with double bookings and no audit trail.

Engineering

Access/refresh JWT tokens with three roles (admin, receptionist, staff); room status is a validated state machine; bookings are protected twice — an application-level overlap check and a PostgreSQL GiST exclusion constraint.

06 · 2025

BhashaSetu

Offline AI translation

A fully offline OCR and translation system for Nepali and Sinhala literature — PaddleOCR, NLLB-200 and FastText running locally behind a Flask API.

Python Flask PaddleOCR NLLB-200 FastText
Repository
Problem

Translation tools assume connectivity and cloud GPUs; heritage and low-connectivity contexts need everything to run on the reader's own machine.

Engineering

A Flask backend orchestrates PaddleOCR for extraction, FastText for language detection and NLLB-200 for offline translation, with local summarization; an Electron-wrapped React frontend consumes the API and models run entirely on-device.
